# UI Guidelines

本项目是娱乐刀战房，UI 的目标是让玩家快速知道“我现在能做什么”和“我身上正在发生什么”，但不能遮挡近战视野，也不能因为频繁提示刷屏。

## 分层原则

| 层级 | 用途 | 推荐形式 | 位置/排序 | 使用时机 |
| --- | --- | --- | --- | --- |
| 入口提示 | 告诉玩家如何打开当前英雄说明 | 常驻 HUD header | `ACTUALLY_LEFT`, `-999` | 全局只创建一次 |
| 当前英雄说明 | 当前英雄技能说明 | 可开关 HUD subtext | `ACTUALLY_LEFT`, `-998` | 按一次互动键打开，再按一次关闭 |
| 资源/倒计时 | 零件、废铁、疯狗时间等会变化的核心资源 | 动态 HUD header | `RIGHT`, 按英雄分配槽位 | 只给本人显示，创建一次并保存句柄 |
| 当前状态 | 当前改装、窗口、债务等持续状态 | 动态或临时 HUD header | 与资源槽位相邻，通常资源排序 `+1` | 状态开始创建，结束/死亡/换英雄销毁 |
| 关键事件 | 低频、高影响事件 | `bigMessage` | 系统默认 | 例如复活甲破碎、疯狗模式开启、改装完成 |
| 频繁反馈 | 高频或普通反馈 | `smallMessage` | 系统默认 | 例如获得零件、废铁增长、短冷却提示 |
| 视觉状态 | 需要所有人知道的战场状态 | 一次性播放效果，必要时持续效果 | 玩家位置 | 持续效果必须保存句柄并清理 |

## 已占用 HUD 槽位

| 槽位 | 当前用途 | 规则/变量 |
| --- | --- | --- |
| `ACTUALLY_LEFT -999` | 全局“按互动键打开/关闭当前英雄技能说明”提示 | `[hud] create ability guide prompt` |
| `ACTUALLY_LEFT -998` | 当前英雄技能说明 | `[hud] open current hero ability guide on interact` |
| `RIGHT -900` | 源氏疯狗时间倒计时 | `genji_ult_window_hud_id` |
| `RIGHT -850` | 托比昂零件 | `torb_parts_hud_id` |
| `RIGHT -849` | 托比昂当前改装状态 | `torb_mod_status_hud_id` |
| `RIGHT -800` | 堡垒废铁 | `bastion_scrap_hud_id` |
| `RIGHT -799` | 堡垒当前改装状态 | `bastion_mod_status_hud_id` |
| `RIGHT -750` | 拉玛刹痛苦值 | `ramattra_pain_hud_id` |

新增英雄如果需要资源/状态 HUD，优先继续使用 `RIGHT` 区域，并按 50 间距分配新槽位，例如 `-700/-699`、`-650/-649`。同一个英雄的资源行使用整十或整百槽位，状态行使用资源槽位 `+1`，避免互相覆盖。

## 使用规范

- 常驻 HUD 必须有 `*_hud_created` 和 `*_hud_id`，避免每帧重复创建。
- 会消失的 HUD 必须在状态结束、死亡、换英雄时调用 `destroyHudText(...)` 并把 id 设为 `null`。
- 动态资源 HUD 优先使用 `HudReeval.VISIBILITY_AND_STRING`，让数值自动更新。
- 关键状态不只用小字提示。比如“疯狗模式开启”“复活甲已破碎”“非法改装完成”用 `bigMessage`，同时需要持续状态时再配右侧 HUD。
- 高频事件只用 `smallMessage` 或完全不提示，避免干扰近战视野。比如小美冰冻触发、获得零件、废铁增长。
- 技能说明只放当前英雄，不再把所有英雄说明堆在一块。
- 说明文字每个英雄最多 4 行左右，写玩法重点，不写实现细节。

## 刀战房 UI 取舍

- 玩家视野中心要留给近战判断，避免常驻中间 HUD。
- 右侧 HUD 只放本人资源和本人状态，不给全体显示。
- 需要全体感知的状态优先用角色体型、颜色效果或一次性特效表达。
- 资源型英雄必须有资源 HUD；纯触发型英雄可以只在技能说明里解释，不强制加 HUD。
- 如果某个效果很强但有代价，触发时用大字告诉本人，让玩家知道自己进入了风险窗口。
