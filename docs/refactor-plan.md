# 重构计划

当前原则：先保护可玩的旧代码，再逐步拆出可维护结构。`legacy/current-workshop.zh-cn.txt` 是回退来源，不直接编辑。

## 当前 OverPy 状态

- 项目里有 `src/main.opy`，但它只是最小占位入口，不承载旧玩法迁移。
- 已通过官方 npm 包安装 `overpy`，项目使用 `corepack pnpm` 管理依赖。
- `corepack pnpm run build` 可以把 `src/main.opy` 编译到 `dist/overpy-smoke.zh-cn.txt`。
- `corepack pnpm run decompile:legacy` 当前会失败，因为 `legacy/current-workshop.zh-cn.txt` 是 RTF 包裹文本，不是干净的 Workshop 纯文本。
- 因此下一步仍然不做大量 `.opy` 迁移；需要先准备干净的 legacy Workshop 文本，或逐条手工迁移并进游戏验证。

## Phase 0：保留旧版

目标：

- 保存 `legacy/current-workshop.zh-cn.txt` 原始代码。
- 确保旧版本可回退，不直接删除或覆盖。
- 建立审计文档和变量映射。
- 已创建 git 仓库、审计分支 `audit/legacy-workshop-review`，并把初始审计提交推送到 GitHub。

## Phase 1：不改变玩法，只修明显结构问题

可选任务：

- 给重复规则重命名，尤其是两条 `二段跳`。
- 删除或解释无意义规则，例如只执行 `A += 0` 的 `规则 1`。
- HUD 改成只创建一次。
- 主机生成机器人增加防连发。
- 文档化所有玩家变量。
- 明确禁用规则归档，不把禁用规则直接迁移成启用玩法。

## Phase 2：修高风险 bug

可选任务：

- 被入侵效果改成每名玩家独立句柄。
- 被入侵持续伤害避免重复叠加。
- 被睡冷却效果避免重复播放。
- 士兵 76 初始化改成真正的初始化。
- 士兵 76 变大/变小增加按键边沿或冷却。
- 天使复活甲重写，去掉危险 `While`。
- 雾子法阵增加 active flag，避免重复触发。

## Phase 3：逐个模块迁移到 OverPy

建议迁移顺序：

1. HUD
2. 二段跳
3. 主机调试机器人
4. 击杀回血
5. 士兵76玩法
6. 被入侵惩罚
7. 被睡惩罚
8. 天使复活甲
9. 雾子法阵
10. 安娜激素控制

每次迁移只处理一个模块，并保留对应旧规则可回退。迁移后先做游戏内粘贴和运行测试，再继续下一组。

## Phase 4：玩法扩展

后续可以再做：

- 新英雄娱乐规则。
- 规则开关和房主配置。
- 更清晰的 HUD/提示文本。
- 调试命令或测试房专用开关。

## 验证策略

- 文档阶段：只检查文件存在、变量映射完整、风险记录清楚。
- 小修阶段：每次只修一个低风险问题，并写清楚进游戏测试方法。
- OverPy 阶段：先确认编译命令，再跑 check/build；失败只记录错误，不乱改旧玩法。
